## 登录问题排查：通行密钥登录报 500（2026-10-14）
- **现象**：登录页点「通行密钥登录」弹「服务异常：SQLSTATE[42S01] ... 1050 Table 'user_passkeys' already exists」。
- **调用链**：login.php(#passkeyBtn) → passkey.js `Passkey.auth()` → `api?m=passkey&a=auth_options`
  → `ApiRouter::passkey_auth_options` → `PasskeyService::authOptions` → `PasskeyModel::ensureSchema()`（报错点）。
- **根因（表前缀白名单缺失）**：`db.prefix='uic_'`（data/db_cred.php），但 `Database::TABLES` 白名单未含
  `user_passkeys`/`webauthn_challenges` → `applyPrefix()` 不给这两张表加前缀；于是 `ensureSchema` 的
  `CREATE TABLE user_passkeys`（裸名）首建成功、`hasTable('user_passkeys')` 却按 `uic_user_passkeys` 查 → 恒为 false
  → 每次都重跑 CREATE → 第二次起 1050。DB 实证：`uic_user_oauth` 有前缀、`user_passkeys`/`webauthn_challenges` 无前缀。
  `data/schema.sql` 已用 `CREATE TABLE IF NOT EXISTS user_passkeys`，但同样因白名单缺失被建成裸表。
- **修复**：
  1. `app/Core/Database.php` `TABLES` 补 `user_passkeys`、`webauthn_challenges`（顺带去重重复项）→ 前缀从此一致；
  2. `app/Model/PasskeyModel.php` `ensureSchema()` 两处建表加 `IF NOT EXISTS`（纵深防御）；
  3. `public/api/index.php` 全局 catch 改为 `Throwable` + 判定 DB 异常：只回「服务暂时不可用，请稍后重试」，
     SQLSTATE/表名等细节仅写 `logs` 表（含 type/file:line）；非 DB 异常保持原样；
  4. `public/assets/passkey.js` `conditionalMediation()` 链尾加 `.catch()`，吞掉条件 UI get() 被中止的 NotAllowedError
     （用户改用其他方式登录时会触发，属正常现象，原来会在控制台刷未处理拒绝）。
- **验证**：新增 `tools/passkey_e2e_test.js`（8/8）：注册建会话 → 虚拟认证器(CDP)注册通行密钥 →
  凭证进 `uic_user_passkeys` → 退出后通行密钥登录 → 会话 uid 一致；`tools/passive_e2e_test.js` 回归 11/11。
- **重要约束**：WebAuthn 要求 rpId 为合法域名；用 IP 字面量（如 127.0.0.1）访问会被浏览器拒（"invalid domain"），
  passkey 登录须走 `localhost` 或真实域名（HTTPS）。E2E 因此统一用 `http://localhost:8099`。
- **残留**：裸表 `user_passkeys`(0 行) / `webauthn_challenges`(1 过期行) 成孤儿（应用已改用 uic_ 前缀），如需可 DROP。
